****************************************************************************************************
*	Altaholic for Vanilla WoW: Change Log							   *
****************************************************************************************************
	v1.4.0
	- Altoholic now requires the ClassicAPI client mod (https://github.com/brues-code/ClassicAPI).
	  Without it the addon only shows a notice at login; your saved data is left untouched.

	- Removed the Ace2, Dewdrop, Tablet and Gratuity libraries. Events, slash commands,
	  localisation and saved variables are handled by the addon itself. The saved data keeps
	  its format, so existing characters carry over.

	- Item tooltips are annotated through OnTooltipSetItem, so item counts, drop source and
	  recipe info now show on every item tooltip (merchant, loot, quest rewards...), not just
	  bags, auctions and chat links.

	- Bags are rescanned once per frame (BAG_UPDATE_DELAYED) instead of once per changed slot,
	  equipment on PLAYER_EQUIPMENT_CHANGED instead of every unit's inventory change.

	- A quest turn-in is added to the completed quests right away, the Attunements tab no
	  longer waits for the next server poll.

	- Fixed errors in the account summary caused by mail sent to an alt of the other faction.
	  The mail was filed under an empty character of the sender's faction; it is now moved to
	  the right character at login, and empty characters are left out of the lists.

	- Added an option to match pfUI's look. Until it is set, it follows whether pfUI is
	  installed.

	- Lists redraw when the client receives data for an item it didn't know yet.

	- Items in the mailbox, and items sent to an alt, are now included in the tooltip counts
	  and in the search. They were stored without a link, so they were never found.

	- Enchants and random suffixes ("of the Owl") are kept for items in bags, bank and
	  equipment. They were always dropped, so such an item showed as its plain version.

	- Item IDs for auctions, recipes and reagents are read directly instead of being cut out
	  of the item link.

	- Removed the "AutoQuery server" option and the list of items it had queried. The client
	  now requests unknown items by itself.

	- The quest log is saved with each quest's own text. Every quest used to get the text of
	  the quest before it. Abandoning a quest now updates the saved log as well.

	- Quests are saved with their ID, and "Are also on this quest" compares the IDs, so two
	  different quests with the same name are no longer mixed up.

	- Reputations are updated when they change, not only at login.

	- Scanning the quest log or the reputations no longer leaves your collapsed headers open
	  or changes the selected quest.

	- "Find Upgrade" for a class role reads item stats from the client instead of the tooltip
	  text. It is faster, works on every client language, takes the random suffix of the
	  equipped item into account and skips items another class only can use.

	- Searching with "recipes" ticked finds recipes by name again. Their names were read as
	  empty, so only a search for nothing listed them.

	- Added the Survival secondary profession: a column on the Skills tab, its recipe list,
	  and "learnable by" on recipe tooltips.

	- Fixed the right-click menu on the auctions/bids list and shift-click on a craft in the
	  search results, neither ever received the mouse button.

	- "/alto search" takes any number of words.

	v1.0.6
	- Fixed an issue with the Bag Usage menu not updating the bags size correctly after
	  upgrading/changing a bag slot.

	- Fixed an issue with E-Mails getting marked as read when a player opens their mailbox.
	  This causes all items in the mailbox to go from (30 to X-num of days left) to 3 days

	  Changed the default to "off (unchecked" and fixed the toggle.

	  code shim. Originally this API didn't exsist in Vanilla WoW but does in BC. Cartographer
	  has a simular shim so this issue was missed in testing before the latest release. This
	  has been fixed and if you have Cartographer or not, this should no longer spam the player
	  with errors.

	v1.0.5
	- Added ChatLink support. Questlinks will inform you which Alts have the quest. Itemlinks
	  will inform you where the item is dropped if it’s gear. If it’s a consumable or any other
	  type of item you can use it will tell you how many you have and which Alts have them. In
	  some cases, it will tell you if an item is a crafted item. “Item Source” can be toggled
	  on/off in the Options panel.

	- Speaking of “…how many you have…”. Item counts! Yes, hover over a piece of Wool, a
	  Bandage, or a healing potion etc. The tooltip will inform you which Alts have it, how
	  much, and tell you if it’s in the Alt’s bank or bags. “Item Source, Item Count Per
	  Character, and Total Item Count” can be toggled on/off in the Options panel.

	- Options… both “Already Known” and “Learnable By…” were at one point combined into one
	  on/off switch. Now, they are separated and can be toggled separately. By default,
	  “Include Already Known” is off and “Include Learnable By” is on. Makes for a cleaner
	  tooltip as there is already a flood of info going to it.

	- All tooltips are now processed not just inside Altaholic but now outside and information
	  is available from Player Bank and Bags, the Mailbox, Auction House, and Chat frames.

	v1.0.3
	- Fixed the Consumable's and Trade Goods search sections. There are no sub-categories for
	  these types of items. Basically, works the same way the Auction House search works. This
	  wasn't available until BC.

	- Fixed a memory leak. I found a few more functions with bugs in them that was inserting [0]
	  keys into tables and then polluting the Saved Variables file which can cause other
	  functions to not find what they are looking for. These were also not getting cleared
	  properly which caused all the cache tables to grow over time. I’ve also inserted some
	  code that will scrub for [0] keys incase I missed some sub-routines.

	- Tooltips will now notify the player when and which characters trade skill database is
	  empty. It’s also now smart enough to know if a character has a particular trade skill.
